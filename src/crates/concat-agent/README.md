# 原生智能体所有权门禁

本模块为持久会话提供唯一执行者与宿主代次门禁，不包含模型调度循环。
原版 Pi（智能体框架）继续负责模型、工具和持久任务的调度。

## 接入顺序

1. 在应用专用本地会话目录取得 `SessionOwner::acquire`（独占所有权）。
2. 此时状态为 `RecoveryRequired`（待恢复核对），禁止开启可调度的会话。
3. 通过只读方式核对原生工程、持久会话、待执行意图、编辑回执及落盘版本。
4. 用户决定继续或丢弃中断任务后，原生界面调用 `confirm_recovery`（记录恢复决策）。传入当前核对结果，不能使用模型输出或旧计划代替。
5. 对每个异步操作调用 `begin`（登记操作），在它的全部回调结束前保留操作许可。
6. 每次真正写入、发起外部调用、派发原生编辑及处理迟到回调时，调用许可的 `with_valid`（原子资格检查）。回调必须持有原代次的许可，不能临时向新宿主索取当前令牌。
7. 原生编辑桥仍须在编辑线程检查当前工程、工程版本、任务取消、幂等请求及全部受影响轨道的锁定状态。本模块不代替这些检查。

`confirm_recovery`（记录恢复决策）只改变门禁状态，不执行恢复、清空任务、重发请求或启动调度。调用方必须先按用户决策处理原队列。所有能够启动原版调度的入口均须经过同一门禁，包括提交、任务或空闲等待、恢复、会话取消、压缩及任务信号。不得直接调用会话取消来清理旧队列，该方法本身会启动调度。

`with_owned`（有效所有权下的同步只读检查）允许在待恢复核对阶段读取当前原生状态，并与撤权保持原子顺序；不得在它的闭包中写入或派发工作。

## 安全交接

1. 调用 `revoke`（撤销执行资格）。此时拒绝新操作和旧回调，仍持有操作系统锁。
2. 停止原版智能体调度，关闭可写会话存储，取消或等待已经发出的操作，释放对应操作许可。
3. 调用 `finish_handoff`（排空并交接）。只有全部许可排空，才释放操作系统锁。
4. 新宿主重新取得所有权，代次递增并重新进入待核对状态。

排空超时返回明确错误，不偷取所有权。宿主销毁会撤权，但在途操作许可继续持有锁，直到排空。操作系统释放异常退出进程的锁后，新宿主也不能直接继续旧队列。

## 持久代次与边界

- 锁文件固定为 `.bk-cat-agent-owner.lock`（宿主永久锁文件），不得删除、重命名或原位替换。
- 存储根先规范化；同一真实目录的路径别名落在同一个所有权域。
- 同一个文件同时承载操作系统独占锁和追加式代次日志；写入及刷盘成功后才发出新代次。
- 仅通过原子首次创建确证的新文件允许从空日志初始化。既存空日志、损坏记录或不完整尾记录均拒绝接管，不自动截断、修复或沿用旧代次。修复需要单独核对与用户授权。
- 首次创建者等待抢先检查空日志的短暂锁释放，其他实例继续非阻塞拒绝。初次并发启动不会因为普通竞争永久遗留空初始化文件。
- 使用应用专用本地目录。本模块不为网络文件系统、外部复制的会话目录、恶意替换文件或绕过门禁的直接写入提供保护。
- 电脑系统在持锁期间禁止其他句柄删除或重命名锁文件。类 Unix（多用户操作系统）平台额外刷写目录项。当前验证目标为进程异常退出；断电、磁盘损坏不属于已执行验收。
- `with_valid`（原子资格检查）内的闭包必须短小、同步，不在其中等待异步结果，不递归调用同一门禁。它用于启动一次操作或写入一次回调，后续回调重新核验。
- 批准恢复后若用户切换工程，桥接层仍须根据实际工程状态拒绝过期计划；本模块只管理存储宿主资格。

## 验证范围

运行：

```bash
cargo test -p concat-agent
```

测试覆盖真实文件锁竞争、真实子进程异常终止接管、持久代次递增、跨存储令牌隔离、迟到回调拒绝、撤权与同步写入的顺序、交接排空、损坏日志拒绝及只读句柄写入失败。

手机新旧运行组件重叠是使用真实操作系统锁的宿主生命周期测试，**不是安卓真机测试**。本模块通过测试也不代表内嵌运行组件、模型流式请求、当前时间线或四个工程崩溃断点已经验收。
