1. 修改前确认工作树、分支、远端、未提交修改及关联工作树，保护原有工作。本次实际工作树为E:\BK-CAT（产品目录）；其临时构建目录内另有未修改的稳定基线工作树，用于比较失败与回归。

3. 产品修改在功能分支完成审查和验证，拉取请求目标为二开集成分支。同步前记录起点与回退点，合入上游时完整记录冲突与解决，不用最新分支静默替换已固定参考。
4. 合并前重新读取实际保护规则与必需检查，普通合并不绕过规则。失败或未执行的门禁明确记录，不提升为发布候选。
5. 采用普通反向提交回退产品修改。不得用破坏性重置、删除工作树、清理用户素材或修改其他项目来“修复”冲突。
6. 发布分支只接收已核验的二开版本。未经双端安装验收、许可/第三方声明/品牌核验，不创建正式发布标签、不对外公开安装包、不改变开源许可策略。

本轮只读核验显示仓库规则集为空；这不替代后续实际合并时重新检查分支保护和必需检查。
