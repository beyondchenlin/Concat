# 文案工程归属修补

日期：2026年11月14日；开发基点：第9号拉取请求提交 `4671fc543b39f2a7d4158cdf016f82158e723b2e`（固定源码标识）。

## 已确认的问题

原生文案控制器把工程规范化目录直接作为文案的工程身份，而数据库在应用数据目录中独立保存。移动目录后查不到原稿；另一份工程复用原目录后会误读旧文案及已选剪辑版本。旧测试只使用两个不同的字符串作为工程身份，没有覆盖原生工程移动和目录复用。需求1.1的数据约束明确要求路径不是唯一身份。

## 实现

- 原生工程顶层增加 `bkCatProjectId`（持久工程标识）。新工程创建时写入；旧工程打开时生成，文案关联前通过原生有序保存使其落盘。标识由系统随机源生成并严格校验；损坏字段不会被自动换成新身份。
- 标识由原生会话持有，在所有原生保存快照写回，从可撤销编辑对象中分离。窗口文案入口复用原生保存完成处理，保留当前会话及版本核对、未保存标记和智能任务保存回执。
- 文案版本按持久身份查询。独立位置登记使用永久内核锁文件和完整临时文件同步后的原子替换，文案读写都先核对实际原生文档身份。
- 工程移动后保留原身份和文案。旧位置仍存在时，读取其真实身份；已被其他工程复用不阻断移动。两个现存位置仍持有同一身份时拒绝副本文案写入，并说明原生剪辑仍可使用。当前修补没有增加“另存独立副本”按钮。
- 旧路径记录始终保留。界面列出旧位置文案，允许只读核对正文；只有用户点击“确认归属，复制旧稿到当前工程”后才在单一事务中复制全部历史及候选。新文案及候选使用新身份，目标不能覆盖已有文案，剪辑版本保持未选择。原文案及原选版完全不变。
- 旧稿复制核对用户刚查看的完整快照；查看后旧稿发生修改时拒绝复制，要求重新核对。任一插入失败撤回整个目标复制，不留下半份文案。
- 原生模板保存不携带来源工程身份；从旧模板新建也使用新工程自己的身份，保留原有模板能力。
- 剪映导入在写入完整文档时保留刚新建工程的持久身份；重复导入相同来源仍生成独立工程身份，来源文件不变。已静态核对全部新建工程调用，模板与剪映是新建后直接写入文档的两个生产入口，其余入口由原生会话接管保存。
- 文案位置登记目录、锁文件、登记文件和原生清单拒绝符号链接；微软平台同时拒绝对应的重解析点。窗口传入的工程目录别名先解析到真实目录核对，保存与回执仍使用原会话路径。损坏登记及无法核对的旧位置保留原文件并停止文案操作。
- 位置登记锁在所有返回和展开路径显式解锁后关闭，避免进程启动期间继承的描述符延长锁寿命；正常操作遇到解锁失败返回错误，原操作失败时保留原失败原因并记录清理失败。新增保留复制描述符的实际锁回归用例，仍待提交后执行。

## 验证状态

### 文案打开的只读边界

打开及重新读取文案先在后台核对磁盘中的原生工程身份。已有相同持久身份时，直接读取文案，不写原生时间线，不产生原生保存回执，不停止已有自动保存计时器，也不清除时间线的未保存标记。准备快照和顺序票据只为旧工程的首次身份保存保留正确顺序，准备本身不表示保存发生。

只有磁盘缺少身份的旧工程才使用会话携带的原生保存许可写入完整快照；已有身份会话遇到磁盘身份被删除时仍被拒绝。只有实际写入结果产生保存回执，通用完成处理继续核对原打开会话及原版本，保存中新增的编辑不会被旧结果标成已保存。界面给出的目录别名先解析为真实目录进行身份检查；有序保存与回执始终沿用原生会话的原路径。

新增真实磁盘用例覆盖：已有身份打开时字节不变、没有回执、较早顺序票据仍能写入；旧工程完整快照先落盘再登记文案归属；被更新票据取代而身份仍未落盘时拒绝绑定；陌生、损坏或被删除的身份保全；目录别名的原路径保存和回执。测试代码已编写，尚未执行；这些用例不代表真实窗口验收。

## 回退与数据保全

不改变现有文案数据库结构，不删除或重写旧路径记录。回退源码前保留原生工程、文案数据库及位置登记；旧版本不了解持久工程身份时仍按旧路径读取，因此不得把回退后的旧视图解释为文案已丢失。明确恢复复制产生的记录保留，不能为回退而删行。

## 原生保存边界增补

复核发现，文案结束保存拒绝身份替换后，原生结束保存仍会独立执行；普通保存和自动保存也共用该入口。只在文案层核对身份不能保护路径中的替换工程。本增补在原有每工程写入互斥锁内核对实际清单，再判断顺序票据，最后沿同一个已核对清单路径原子替换。同身份才能保存；另一身份、损坏身份、损坏或不可读取的清单均保持原文件并返回错误。缺身份的通用快照不能覆盖已经持久化身份的工程。

旧工程首次获得身份采用原生会话的私有保存许可。许可绑定会话首次读入的完整文档内容指纹、目标身份和实际目录对象，随原生保存快照共享。它不进入工程文档或外部协议。首次成功落盘，或者观察到同一身份已经落盘后，所有共享许可永久失效；此后清单被删除或恢复成无身份旧文档仍拒绝保存。磁盘仍无身份、且没有实际写入的顺序跳过不消费许可，也不能成为文案已完成绑定的凭据；顺序跳过前已经观察到同一持久身份时，许可仍会消费。

初始化目录证明保留打开的目录句柄。类统一系统核对设备号和索引；微软系统核对卷号和128位文件标识，接口不可用时拒绝首次初始化，已经具有持久身份的工程不增加该初始化能力要求。目录别名按实际目录对象核对，外层原始会话路径和保存回执不变。原先不存在的工程目录只能排他创建最后一级；创建完成后共享许可记住新目录对象，后续失败不会把它误当成外部新目录。原先已有的目录被替换时，即使旧文档字节相同，也不能借用旧许可首次绑定。

生产保存入口已经核对：原生会话、窗口普通及自动保存、工程关闭和终止保存使用携许可入口；模板和剪映导入携带刚新建工程已落盘的相同身份，继续使用严格通用入口。文案打开的携许可接线由独立只读打开修补共同合入。合法旧版无身份文档之间的通用保存继续保留；既有并发和顺序测试只把最小夹具补成合法原生文档，其时序和结果断言保持不变。

新增11项真实文件保存回归覆盖：双工程替换后延迟自动保存与手动保存拒绝；身份移除、损坏及清单消失；通用旧版兼容与身份降级拒绝；原始内容改变与失败重试；共享许可消费及观察已落盘身份后的消费；身份与位置借用拒绝；相同旧内容的整目录替换；空目录和新目录首次创建；两份旧版会话并发首次绑定；旧清单文件名保留。初次提交时尚未执行，原计划命令为：

```sh
cargo test --locked -p concat-host --test project_identity
cargo test --locked -p concat-host projects::tests
cargo test --locked -p concat-host session::tests
```

本增补复用原生保存的进程内有序写锁和临时文件原子替换，不把无协作外部程序修改文件的任意竞争写入称为已验收。完整编辑状态终止回归与窗口只读打开回归在整合候选上单独执行。
