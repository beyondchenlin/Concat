## 核对结果

| 核对重点 | 代码事实与回归证据 | 结果 |
| --- | --- | --- |
| 五种中断事实 | 意图、改变回执、精确保存证据、送达确认各自持久化；保存先到时保留捕获文档与候选操作身份，没有结果回执仍为“结果未知” | 通过 |
| 原回执版本绑定 | 改变结果必须匹配原会话，结果版本严格大于预期版本；保存仅关联精确会话及版本；旧保存不能给新版本或其他操作作证 | 通过 |
| 早到保存 | 持久附表保存原生代次、工程、会话、版本、原文档及摘要，并绑定当时实际在途操作集合；后到回执只关联原操作身份 | 通过 |
| 新进程复用编号 | 即使会话及版本数字重复，新调用仍是不同操作身份；旧保存候选不会成为新调用证据；普通新保存也不补写旧未保存回执 | 通过 |
| 旧代结果隔离 | 三类结果入口要求当前账本实例实际准备过该操作；重开后不能补改变、拒绝或不变回执来消除未知事实 | 通过 |
| 全历史复核 | 原生读取并比较完整操作、保存候选及复核记录；展示最近 32 条只限制详情页，40 条大回执测试仍将全部 40 条纳入核对 | 通过 |
| 复核不是伪造成功 | 确认只写复核记录，不改原始回执、保存或送达字段；未知继续未知，已应用未保存继续保持原状态；旧操作仍不能重放 | 通过 |
| 工程之间隔离 | 同时存在两个工程待核对时，只确认本工程，另一个工程保留原状态；只有其他工程待核对时不能通过当前工程处理 | 通过 |
| 新鲜证据与代次 | 复核对象绑定存储根、原生代次、完整账本及当前工程文件摘要；变更文件、旧代证据、已消耗的旧快照均拒绝 | 通过 |
| 保存通知 | 重新打开账本不会重新排送旧通知；当前原生会话只接受实际进入本组件待确认集合的操作，错误代次与重复确认均拒绝 | 通过 |
| 只读检查及兼容 | 未确认前不初始化账本、不创建新增证据表；已有旧账本仅在原生批准后增加审过的附表；原始操作记录不改写 | 通过 |
| 停止响应 | 读取文件、解析和完整历史扫描不长时间持有所有权门锁；写入前重新核验本代许可，停止不会等待只读扫描完成才撤销 | 通过 |
