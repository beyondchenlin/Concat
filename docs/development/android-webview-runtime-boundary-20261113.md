## 五、为何不能用简化垫片通过门禁

1. **语法层。** 原样包保留异步私有方法及逻辑赋值。构建目标调整只能解决对应语法转换，不能补齐下列运行能力。
2. **顶层初始化层。** 原版正则缓存创建终结通知注册器；原版数据库结构版本还在顶层调用数组相对位置接口。运行库未完成初始化时，引导脚本不会建立原生通道。
3. **弱引用语义层。** 原版变更跟踪器用弱引用保存竞争编辑上下文。已丢弃上下文可回收，仍存活的上下文在成功提交时必须失效。用强引用替身会保留已丢弃上下文；按容量任意淘汰又不能等价代表真实对象是否存活。正则缓存的空终结通知实现同样失去回收。修改原版消费者策略属于改变组件实现，不是透明宿主适配。
4. **启动与恢复接口层。** 原生通道客户端在加载完成事件前生成密码学随机标识；恢复读取路径使用取消信号抛错接口。只让解析通过仍不能完成这条路径。
5. **后续原版能力层。** 原包还包含承诺对象外置完成器、组合取消信号及结构化克隆等调用。启动通过也不能自动证明模型执行、取消及清理路径完整兼容。

上述判断由两位代理分别阅读实际包、固定源码和旧内核输出后交叉核对。没有写入空回收器、弱引用强持有替身、取消空实现或虚构恢复事件。
