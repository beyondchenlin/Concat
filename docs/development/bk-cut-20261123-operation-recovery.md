## 五种故障状态的事实合同

| 故障位置 | 能证明的事实 | 不能据此宣布的结论 |
| --- | --- | --- |
| 意图已提交，原生尚未执行 | 计划与原始调用身份已入库，应用回执缺失 | 不能从缺回执证明从未执行，也不能自动重放 |
| 原生已执行，应用回执尚未入库 | 若没有其他持久证据，仍只能报告操作结果未知 | 不能因为用户曾看到变化而伪造持久回执 |
| 应用回执已入库，工程尚未保存 | 当时的应用结果和精确版本已记录，对应保存尚无证据 | 不能宣称该修改已保存在当前磁盘工程 |
| 对应版本保存已核实，完成通知尚未确认送达 | 保存证据存在，通知送达仍未确认 | 复核操作不等同通知送达，不自动填写已通知 |
| 保存先到，应用回执后到前异常退出 | 完整原生捕获文档、版本、文件摘要及当时在途操作候选集合持久存在 | 保存文档证据单独不能证明某一具体操作成功 |

前两个断点在缺少其他持久结果时有相同的“未知”结论。这是证据边界，不是把两个测试断点合并。第五种状态在事实摘要中另计“有保存文档捕获、但无操作回执的操作数量”，不当作唯一文档数。

## 实现与兼容规则

- 原有 `operations`（操作表）和历史回执保持原结构。只读检查不会创建或迁移数据库。原生明确授权后打开写日志时，先检查既有表及触发器，再按已实现的兼容规则新增 `saved_documents`（文档捕获表）和 `operation_reviews`（明确复核表）。未知或不符合预期的附表结构会拒绝使用。
- 捕获保存包含工程路径、所有者代次、原生会话、精确版本、实际磁盘字节摘要、完整捕获文档和当时的操作候选身份。后到回执只关联同操作、同工程、同会话、同版本的证据，不能仅因新进程复用了会话编号就套用旧保存。
- 保存回调只为本日志代真正准备过的操作写保存证明。成功、拒绝和无变化三种回执也只接受当前代真正准备过的操作；新所有者不能给旧未知操作补写结果。
- `inspect_recovery`（只读恢复核对）返回完整、可比较、绑定所有者代次的事实。核对包括当前工程磁盘文件的实际摘要、原始日志行、所有文档捕获和已有复核记录。读取文件时不持有所有者写锁，停止动作可撤销原代次。
- `reconcile_review`（确认已展示事实）仅在原生已确认授权后执行；重读并比较完整证据，在同一数据库事务内记录复核。工程或日志改变、旧所有者核对和跨工程处置均被拒绝。复核原调用后再提交同一旧调用仍然拒绝重放。
- 两工程同时有未结项时，只允许确认当前工程，完整保留另一工程原记录和未复核计数，避免互相阻塞。原版共享库的后续调度是否安全由上层当前工程恢复流程另行控制；本接口不自行调度任何任务。
- `facts()`（对外事实摘要）保留完整状态计数、精确核对指纹、当前文件证据以及本工程和其他工程的状态统计。仅将最近32条未复核身份作为显示页，并明确显示总数、已显示数与未显示数。原生完整核对与复核仍覆盖全部历史；显示页大小不是任务、请求、词元或历史总量上限。
