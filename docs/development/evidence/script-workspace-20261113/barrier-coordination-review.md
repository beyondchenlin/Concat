## 已发现错误路径与修补行为

原测试的第二线程在 `ScriptStore::open`（打开文案存储）返回错误后，会在屏障前断言失败，无法抵达屏障。第一线程仍等待第二方；主测试按句柄顺序先等待第一线程时，错误就变成无界等待。

候选先保存打开存储的 `Result`（成功或错误结果），完成本夹具内确定有效的草稿准备，再让两个线程都抵达原屏障。屏障释放后，原 `unwrap`（成功断言）才检查打开结果：

- 打开返回错误仍触发测试失败，没有转为允许结果，没有吞掉错误，也没有重试或回退。
- 第二线程打开返回错误时，第一线程不再因为缺少屏障参与者而留在屏障。
- 两方打开成功时，仍从同一个旧快照出发，屏障释放后分别调用真实持久化保存。恰好一个保存成功、另一个旧快照被拒绝、被拒草稿完整保留及最终仅有两个版本的断言全部保持原样。

本修补针对“打开操作已经返回错误”这一已发现路径，不宣称消除操作系统文件调用本身无法返回、进程强杀或资源耗尽等其他终止情形。
