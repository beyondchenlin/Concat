# 停止后显式放弃原版未完成任务

本记录隶属第13号草稿拉取请求，基于1.1需求中“停止不能自动恢复收费操作、持久会话必须可核对恢复、未核对原生编辑记录不能跨越”的要求。它是本次模型任务接线的实际恢复缺口修补。

## 真实缺口及处理

原先用户按“停止”会先撤销运行组件。原版持久数据库可能留下非终态任务，而重新连接时原生恢复检查拒绝继续，也拒绝放弃，因此旧任务可能使该用户长期无法再次启动模型聊天。保持旧任务停止是正确的，但缺少明确放弃入口。

本轮新增“放弃未完成任务并打开会话”按钮，执行以下真实边界：

1. 原生核对当前工程的持久身份、真实清单文件、路径、打开会话、工程版本、原生数据库结构与未核对编辑日志。三类编辑记录只要仍待工程核对、已应用未保存或已保存未通知，任何放弃都拒绝。
2. 从既有原生历史映射中只读取得当前工程全部聊天、文案和剪辑会话编号。只读位置登记沿用永久锁和副本拒绝规则，不创建、移动或改写记录；当前工程的原始路径仍先执行持久身份校验。未知归属拒绝。
3. 用户明确点击后，原生发出本次单一恢复决策的会话范围，不发模型费用许可。恢复过程在进入就绪前先使用固定原版存储组件扫描完整任务和提交记录；对其他工程、未知版本、未知状态或可能触发延期网络轮询的检查点拒绝，不能因为筛选状态遗漏记录。
4. 通过完整预检后才打开固定原版执行器。原版打开会将历史运行中状态改为待处理，因此前置检查必须先于这一状态变化。随后使用原版取消提交和取消任务接口先标记所有历史工作停止，再调用原版等待接口排空，不另外编写调度器、不调用模型和编辑工具。
5. 原版检查确认为无未完成项后，还要让原生层重新核对当前工程、真实清单、历史映射和三类编辑日志，确认原版数据库的未完成计数为零。原生终核只允许本次明确放弃使用一次；失败后不开放新任务，重连仍须重新核对。成功后才进入可发送状态，旧历史消息保留。

固定原版数据库组件对已兼容数据库的打开会执行建表存在性检查和版本记录忽略写入；该公开接口没有纯只读打开选项。因此本方案先由原生验证固定数据库版本、必需对象是普通表，并依靠原生数据库授权器禁止触发器或视图执行；这里没有逐列比对全部建表定义。随后使用原版存储接口做无状态筛选的全量预检。外工程、未知版本和异常状态拒绝时，任务、提交和消息记录不得被改写。不能把这一过程宣称成从物理文件打开开始全程无事务，也不能据逐条记录相等推断数据库文件字节完全不变。

## 审查范围

作者及独立复核覆盖了工程原始路径和符号链接、原版与旧版清单文件选择、永久锁、历史会话范围、用户确认防伪与重复使用、任务类型/版本/阶段、全量记录扫描、原版取消后的排空、原生终核和失败不授予权限。

测试分别要求：原生持久文件与位置登记的拒绝路径；真实原版会话数据库在停止、重开和明确放弃后的终态及消息保留；其他工程、未知状态、延期网络轮询、原生编辑未核对和迟到请求的拒绝。测试需先提交草稿请求，再正常获取固定提交到隔离工作树后执行。

本记录创建时新增恢复代码仍未完成固定提交验证，不能作为功能通过证据。收费渠道、真实电脑窗口和安卓组件生命周期仍需独立验收。
