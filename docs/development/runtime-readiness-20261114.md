# 运行组件能力检测与加载失败收尾

## 问题与受测基点

本修补基于第7号拉取请求头提交 `cb224f69471088a1a349f6d54be7a6fb8d92c18d`（提交标识）。移动运行43457220451已经结束：两架构构建成功，接口35及网页组件124完成原生恢复；接口30及网页组件83没有在60秒观察内完成恢复。两份最新设备构件编号为14057950205、14056754353。

原代码直接加载固定脚本包。网页脚本解析失败时，既不能发送加载完成事件，也不能向原生界面提供固定类别的错误；设备验证脚本的60秒截止只使验证失败，不能替产品处理持续等待。

## 实现

1. 原生编译内置的传输脚本使用旧引擎可以解析的第五版脚本语法，先核验运行能力，再依次加载固定运行包及引导包。没有引入替代原版实现、能力垫片或按浏览器版本号猜测通过。
2. 能力契约覆盖基础网页数据接口、弱引用及内存回收通知、安全随机标识、取消信号及取消原因、数组相对访问、对象自身属性查询、异步任务外置完成器和结构化复制。所需能力来自固定原版的模式缓存、变更跟踪、数据库迁移及会话代码，以及本项目原生通道和执行门。
3. 资源错误、脚本解析/执行错误、缺少运行库、缺少引导回执，都转换成固定错误类别。原生侧将类别映射为中文提示，不使用网页提供的错误正文、文件名、对话、密钥或数据库内容。
4. 原生消息线程对首次加载施加30秒单调截止。收件不能延长截止，截止后到达的加载完成事件不能启动运行库；页面完全不执行时仍由原生侧收尾。加载完成只取消这个加载截止，不批准恢复、工具调用或模型费用。
5. 失败先撤销原生执行资格，再请求平台销毁；只有真实销毁确认才能结束原生会话并释放独占所有权。关闭回调中的通用原因不能覆盖引起退役的首个明确错误。页面退役还会拒绝迟到加载、迟到消息和重复错误事件。

原生加载截止从平台工厂返回并就绪后开始，覆盖其后排队的平台创建、焦点等待及脚本加载；它不承诺可打断平台工厂内部同步阻塞。生产平台工厂按现有协议只排队创建。

## 验证状态与执行顺序

此提交准备阶段只进行源码阅读与固定编译器1.93.1的格式化编辑。按本轮要求，新增测试须在拉取请求上传后执行；本记录不宣称新增测试已通过。

待执行的脚本测试覆盖：缺少每组能力时两份原包均不加载；运行库和引导顺序；真实解析异常经浏览器事件入口转换为固定错误；丢失资源和引导回执；重复及迟到回调；页面退役后的消息拒绝。浏览器接口由明确测试夹具提供，不能把这些测试写成模拟器或真机验收。

待执行的原生测试覆盖：静默加载超时、实际磁盘所有权在销毁确认前持续占有、迟到加载拒绝、已知和未知错误内容不能泄露、明确错误跨关闭确认保留、加载完成不能跳过恢复确认，以及生命周期停止优先于迟到加载结果。
