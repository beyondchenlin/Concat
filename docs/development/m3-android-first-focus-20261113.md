# 第三组安卓首次前台焦点修补

日期：2026-11-13

## 本次结论

本次修复了一个确定的启动时序缺口：原生界面事件循环的首次计时器请求创建智能体宿主时，安卓活动尚未获得首次窗口焦点，原代码立即结束该组件。新代码仅为本次尚未打开网页的组件等待首次前台焦点，使用十秒绝对截止时间；暂停、保存活动状态、销毁、主动关闭会永久取消本次创建。恢复前台不会重建已经退役的组件。

实际完成了安卓源码编译、十二组生产策略测试和字节码生成。新代码的完整原生链接、安装包制作、模拟器启动和真机执行均未执行。旧运行的设备日志只证明启动先于窗口首次显示而结束；它未输出具体拒绝谓词，不能写成已经由设备日志直接确认了某一个条件。

## 源码定位与行为

固定实际检出提交的 [原生启动入口](https://github.com/beyondchenlin/Concat/blob/b584d2f05c805ef0bdcdeba58632747bd9d9ce3e/src/crates/concat/src/lib.rs) 在事件循环中的零延迟计时器启动宿主；[原安卓宿主](https://github.com/beyondchenlin/Concat/blob/b584d2f05c805ef0bdcdeba58632747bd9d9ce3e/src/crates/concat-android/java/BKCatRuntime.java) 在创建入口把没有窗口焦点直接作为关闭条件。计时器触发不保证安卓窗口已经获得焦点，这是源码中的确定缺口。设备时间线与这个缺口吻合，旧日志没有记录具体分支。

修补后，创建入口仍先核验活动身份、生命周期观察器、暂停、结束和销毁状态，并拒绝重叠组件。仅首次尚未开启的同一个组件能够等待焦点，等待本身不创建网页、不调度任务、不发起模型请求。生产策略按安卓单调时钟固定十秒截止点；重复通知不能延长截止时间，恰好到截止点的首次焦点也被拒绝。

焦点监听装在原活动的装饰视图上，不替换原生界面、不夺取输入。挂接前的观察器在窗口挂接时会被合并，所以取消时读取该视图的当前观察器移除监听。每个组件最多进入一次实际网页创建。活动恢复只更新暂停状态，没有创建调用。

所有退役路径仍先撤销原生执行资格，再取消首次等待，最后处理真实网页销毁。网页销毁抛出异常时不发关闭确认，原生所有权仍被保留。固定原因码只包含封闭枚举值，不包含组件能力令牌、消息内容、凭据或工程路径。此前资源白名单、消息来源、唯一执行者及严格核对态成功标记没有放宽。
