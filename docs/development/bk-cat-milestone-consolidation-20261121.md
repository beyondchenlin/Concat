## 源码裁决

### 纳入当前实现：真正按用户行为启动运行组件

已提交的历史设计要求普通手动剪辑不分配智能体运行组件。当前窗口启动入口已经保持静默，但真实工程打开入口仍会自动连接。这是旧副本揭示的真实遗漏。

本轮整合的行为边界：

1. 尚未启用智能体时，首次手动打开真实工程后保持运行组件未启动，手动剪辑和播放不依赖智能体。已经主动启用的会话在切换工程时继续执行现有撤权和重新绑定流程。
2. 首次明确发送时，允许在加载早期保存一个待发送意图。进入恢复或激活阶段后，接受新的等待意图必须已有完整、干净的原生快照；快照缺失时保留原有恢复核对入口。
3. 等待阶段不发送模型任务，不授予模型或工程编辑权限，不读取凭据。
4. 就绪后重新核对组件、工程、会话、修订、配置和恢复状态，再进入现有提交及审批路径。
5. 等待意图只领取一次。停止、换工程、启动失败、超时或恢复阻断清除它；迟到事件不能重新执行。
6. 草稿继续仅在有效接受回执后清理；拒绝与失败保留输入。

旧代码不能直接覆盖当前实现：它包含反向锁顺序、旧输入硬上限、旧失败清理方式，并缺少当前审批任务开始接线。整合保留当前完整通信帧预算、输入拒绝分类、停止撤权与恢复核对。

### 保留当前实现：布局与真实错误处理

以下旧方案已有明确替代，不合入：

- 恢复至 1,300 像素侧栏的旧偏好方案。当前已验收策略的侧栏范围为 320 至 840 像素，并按窗口可用空间进一步限制。

- 只断言回调发生的旧首发测试。新回归需要覆盖等待、就绪、单次领取、停止退役和接受回执时机。
- 旧布局测试及其专用依赖不能因存在于旧目录就自动纳入。
