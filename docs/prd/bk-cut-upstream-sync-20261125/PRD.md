## 3. 产品目标、非目标与成功标准

目标一：保留全部已确认产品能力，同时接收上游导出、字幕、性能、原生安卓等功能，形成同一上游基线的双端产品。
目标二：上游承担媒体、剪辑、预览、字幕、特效、调度及导出；自有层承担智能体、文案、模板、权限、产品体验、品牌和国内配置。
目标三：消除重复引擎及不必要的上游文件改动，持续缩短同步成本。以原有文件变更数、补丁原因、实际冲突数、解决耗时、回归失败数衡量，不为数字牺牲安全。
目标四：真实工程唯一事实源，人工和智能体共用原生编辑与撤销历史；新上游能力不自动扩大智能体权限。

非目标：不重做剪辑引擎，不提前采用尚未接入实际编辑链路的新文档模型，不开发第二套智能体，不强行统一桌面与手机界面代码，不拆分成多个仓库，不扩展新商业功能，不实现未经确认的自动导出权限，不承诺支持未验收平台。本轮不把上游开源授权视为闭源商业授权。

## 5. 架构边界和依赖原则

逻辑链路：桌面 Slint／安卓 Compose→ 自有产品层与智能体 → 权限及工具目录 → 统一编辑接口 API／MCP→ 原生安全事务和实际工程所有者 → 上游剪辑核心。普通人工剪辑仍沿原生路径，不依赖智能体进程或模型服务。

| 边界 | 职责 | 实施规则 |
| --- | --- | --- |
| concat-agent（现有智能体模块）及 agent-runtime（运行环境） | 对话、计划、模型、技能、任务、停止 | 保留现有固定组件和隔离；不直接写工程 |
| bkcut-product（建议产品配置边界） | 名称、资源、默认值、发行渠道 | 数据与平台适配分离；不硬编码用户目录或密钥 |
| bkcut-policy（建议策略边界） | 权限、能力白名单、影响范围、审计 | 原生提交前强制校验，客户端不能自行放行 |
| bkcut-adapter（建议适配边界） | 统一请求契约、版本适配、会话连接 | 桌面与移动各自实现宿主适配，共用安全规则 |
| bkcut-ui（建议界面边界） | 助手、文案、设置、审批及挂载 | 自有界面独立，保留必要的上游挂载点 |
| 上游核心 | 媒体、渲染、时间线、编辑命令、撤销、导出、字幕及调度 | 采用新上游实现，安全检查可在原生执行边界保留必要扩展 |

上述为逻辑模块建议，优先使用现有编译包和文件结构；不为名称强行拆包，不引入循环依赖，不要求核心层依赖桌面界面或智能体运行时。自有业务应依赖稳定契约，不依赖内部窗口类型。服务端适配器可以调用原生编辑器以实现接口；禁止模型、脚本、智能体客户端绕开适配器直接修改工程数据。普通人工原生编辑不强制绕经智能体接口，但人工编辑与智能体编辑最终使用同一个原生工程所有者和编辑历史。

保留 TypeScript接入固定 Pi1.5.2版、持久会话及既有原生凭据/权限桥。桌面继续使用 WebView2（微软内嵌网页运行组件）；安卓改用原生界面不意味着删除智能体运行所需 WebView或原生桥。先迁移现有运行能力，再考虑独立优化；不得未经批准升级智能体固定版本、重写运行时或另造一套移动端智能体。

每个必要的上游接入点有唯一清晰职责、最小公共契约、单元或集成测试；禁止整页复制上游界面、在多个地方重复业务规则、用标记注释替代测试。启动入口收敛为小型安装/注册点，项目打开、切换、关闭、暂停、停止与释放采用明确生命周期。复杂逻辑不得藏在单一初始化函数中。

## 6. 同步策略、改动分类与维护制度

### 6.1 分支与同步规则（S01–S07）

## 14. 回退与故障处理

候选未验收则不进入开发分支，隔离并保留证据；已合入的局部问题使用正常修复或反向提交，不改写公开历史。反向撤销合并后未来同步需评估已合并祖先及被撤销变更，不能盲目重复合并。

正式版本异常先停止升级推广，确认安全旧版本和工程格式；停止新版本写入并备份当前数据后，使用已验证安装包及升级前备份恢复，保留新版本产生的工程/成片和故障日志。旧程序不支持新格式时禁止覆盖唯一工程。安卓降级受系统版本和签名规则约束，不保证旧包直接覆盖；可选择经确认的旧代码修复版以递增版本号重新发布，或保持旧/新应用隔离并执行已验证的迁移回退。禁止绕过系统降级和签名安全。未能证明可恢复路径时阻断发布，明确新格式的兼容限制及人工操作。
